# Play Console Readiness Checklist (Vowz PWA → TWA)

Use this before submitting the `.aab` generated by [PWABuilder](https://www.pwabuilder.com/) to the Google Play Console. Every item must be green before hitting **Send for review**.

Cross-refs: [`docs/pwabuilder-android.md`](./pwabuilder-android.md), [`docs/ios-pwa-reinstall-qa.md`](./ios-pwa-reinstall-qa.md).

---

## 1. App content & policy (Policy → App content)

- [ ] **Privacy policy URL** — set to `https://vowz.me/privacy`. Public, non-auth URL describing data collected, purpose, retention, third parties (Razorpay, Cloudflare R2, Lovable Cloud, Google Sign-In), and deletion contact.
- [ ] **App access** — provide a demo login (test email + password) so reviewers can enter the editor without paying. Note the 7-day trial.
- [ ] **Ads** — declare **No, my app does not contain ads**.
- [ ] **Content rating** — complete IARC questionnaire. Expect **Everyone / PEGI 3**.
- [ ] **Target audience & content** — Age 18+. Do **not** tick "also for children".
- [ ] **News app** — No.
- [ ] **COVID-19 contact tracing** — No.
- [ ] **Data safety form** — see Section 2.
- [ ] **Government app** — No.
- [ ] **Financial features** — No (Razorpay is checkout, not a financial product).
- [ ] **Health** — No.

## 2. Data safety form (Policy → App content → Data safety)

Declare exactly what the PWA collects. Do **not** overstate.

| Data type | Collected | Shared | Purpose | Optional? |
|---|---|---|---|---|
| Name | Yes | No | Account management, app functionality | Required |
| Email address | Yes | No | Account management, communications | Required |
| Phone number | Yes (if entered) | No | App functionality (RSVP/contact) | Optional |
| User photos | Yes | No | App functionality (wedding site media) | Optional |
| Payments info | No (Razorpay handles; token only) | — | — | — |
| Precise location | No | — | — | — |
| Approximate location | Yes (IP-derived, currency) | No | App functionality | Required |
| App activity / interactions | Yes | No | Analytics, app functionality | Required |
| Crash logs / diagnostics | Yes | No | Analytics | Required |
| Device or other IDs | Yes | No | Analytics, fraud prevention | Required |

Security section:

- [ ] **Data is encrypted in transit** — Yes (HTTPS enforced).
- [ ] **Users can request data deletion** — Yes, via in-app account settings + email to support.
- [ ] **Committed to Play Families Policy** — N/A (18+).
- [ ] **Independent security review** — leave unchecked unless a report exists.

## 3. Store listing assets (Grow → Store presence → Main store listing)

- [ ] **App name** — `Vowz — Wedding Websites` (≤ 30 chars).
- [ ] **Short description** — ≤ 80 chars, e.g. `Design a beautiful wedding website in minutes.`
- [ ] **Full description** — ≤ 4000 chars, feature bullets + trial + support email.
- [ ] **App icon** — 512×512 PNG, 32-bit, no alpha, matches glossy-white iOS icon (`bun run validate:white-glossy`).
- [ ] **Feature graphic** — 1024×500 PNG/JPG, no text near edges.
- [ ] **Phone screenshots** — at least 2, up to 8. 1080×1920 portrait. Use `public/screenshots/mobile-*.jpg`.
- [ ] **7-inch tablet screenshots** — optional but recommended.
- [ ] **10-inch tablet screenshots** — optional.
- [ ] **Promo video** — optional (YouTube URL).
- [ ] **Category** — Lifestyle. Tags: Wedding, Planner, Website builder.
- [ ] **Contact details** — support email, website `https://vowz.me`.

## 4. TWA / package readiness

- [ ] Package name locked (e.g. `me.vowz.twa`). Never changes after first upload.
- [ ] `public/.well-known/assetlinks.json` deployed with the **release** signing key SHA-256 (from Play Console → Setup → App integrity → App signing key certificate).
- [ ] Verify: `curl https://vowz.me/.well-known/assetlinks.json` returns 200 JSON.
- [ ] Manifest `start_url`, `scope`, `id`, `display: standalone` frozen — changing these post-install requires reinstall.
- [ ] Service worker `/sw.js` reachable and returns 200 in production.
- [ ] Lighthouse PWA audit ≥ 90 on the published URL.

## 5. Release track & rollout (Release → Production)

1. **Internal testing** — upload the `.aab`, add tester Google accounts, install via opt-in link, confirm the app opens **without the Chrome URL bar** (proves Digital Asset Links).
2. **Closed testing (optional)** — 20+ testers for 14 days is required only for personal developer accounts created after Nov 2023.
3. **Production release**
   - [ ] Release name: `1.0.0 (1)` — matches `versionName (versionCode)` in the `.aab`.
   - [ ] Release notes ≤ 500 chars per locale.
   - [ ] Countries: start with India + United States, expand later.
   - [ ] Staged rollout: **20 %** for 48 h → 50 % → 100 %.
4. **After approval** — monitor Play Console → Quality → Android vitals for ANRs/crashes for 72 h.

## 6. Updates (subsequent releases)

- [ ] Bump `versionCode` (integer, +1) and `versionName` in PWABuilder before regenerating `.aab`. Play rejects duplicate `versionCode`s.
- [ ] Re-run `bun run build` so the `iconCacheBust` plugin refreshes icon/splash query params.
- [ ] Re-run `bun run validate:white-glossy`.
- [ ] Publish site first, then upload `.aab` (TWA loads live URL — the web deploy is the real release; the AAB shell only needs re-upload when manifest, icons, or package metadata change).
- [ ] Staged rollout again (20 → 50 → 100 %).
- [ ] Bad release? **Halt rollout** in Play Console, then push a fixed web build — TWA users pick it up on next launch without a Play update.

## 7. Common rejection reasons to pre-empt

- Missing or inaccessible privacy policy URL.
- Data safety form contradicts what the app actually collects (Play cross-checks with automated scans).
- Screenshots contain device frames, Play badges, or misleading UI.
- App icon has transparent background or rounded corners baked in (Play adds the mask itself).
- `assetlinks.json` missing → app launches with a browser URL bar, failing the "Immersive experience" check.
- Package name reused from a previously suspended app.
